## Evening (~15:30–16:45) — Harness laptop-agnostic pass + architectural decision

Triggered by a cloud-agent session report: every hook command in `.claude/settings.json` was hardcoded to `/Users/ahmedomrane/Workspace/...`, violating the laptop-agnostic constraint and silently no-op'ing on Linux/cloud hosts.

- **Investigation surfaced 9 violations**: 7 hook command strings in settings.json + setup.sh's hardcoded memory slug `-Users-ahmedomrane-Workspace`. Hook scripts themselves were already mostly portable (4 of 7 used `${CLAUDE_PROJECT_DIR:-$(pwd)}`).
- **Skills audit added 6 more violations**: tmp-cleanup (executable `find` command + guardrail), log-decision (DECISIONS.md path), check-linear-card-paths (3× workspace root in operative instructions), arch-review (cosmetic doc reference). render/SKILL.md flagged then carved out — `~/Workspace/tmp/` is intentional local/interactive-only.
- **Web research updated the fix shape**: cwd is NOT guaranteed to be project root per official docs (invalidating the `$(pwd)` fallback). `$CLAUDE_ENV_FILE` (available in SessionStart hooks) was discovered — writing `export CLAUDE_PROJECT_DIR=...` to it makes the variable available in all session Bash tool calls, not just hook subprocesses.
- **Architectural research** triggered by Ahmed's question "should skills/hooks/memory be split into their own submodules?". Answer after deep research: no, keep embedded. Anthropic closed submodule support as "not planned" (#7852). Community converged on two patterns: dotfiles-style `~/.claude/` repo (solo machine sync) and plugin marketplace (multi-consumer distribution). Plugin is the right primitive if/when harness becomes a productized asset; submodule is the worst of both worlds.
- **One PR shipped (PR #67, branch `omraneah/settings-laptop-agnostic`)**: 10 files, 2 commits. Local audit caught a real bug — `post-edit-typecheck.sh` has `set -u`, and `PROJ_DIR="${CLAUDE_PROJECT_DIR}"` raised unbound variable before the `[ -z ]` guard could fire. Fixed with `${CLAUDE_PROJECT_DIR:-}`. Merged + cleaned up.
- **Skill(*)** added to settings.json allow list per Ahmed's directive ("never ask me to use a skill again").

### Session decisions

- Keep harness embedded in workspace root. Do not move to git submodule. Plugin pattern is the right primitive *if/when* harness becomes a productized or multi-consumer asset.
- Hooks now require `$CLAUDE_PROJECT_DIR` to be set. Silent exit (exit 0) if unset — `$(pwd)` fallback was unreliable per official docs.
- `$CLAUDE_ENV_FILE` export pattern adopted in `session-start.sh` so `$CLAUDE_PROJECT_DIR` is available in all session Bash tool calls.
- `render/SKILL.md` `~/Workspace/tmp/` paths intentionally local-only — Marky is interactive-mac-only by design, cloud agents don't use it.
